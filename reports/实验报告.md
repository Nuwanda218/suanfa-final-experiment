## 摘要

本实验针对经典组合优化问题 0/1 背包问题，选取 FSU、UU、JJ 三类公开数据源，分别实现动态规划、回溯法和贪心算法三种求解策略，并从正确性、运行时间、空间开销、近似误差、搜索效率和困难实例适用边界等角度进行对比分析。实验程序采用 C++17 实现，数据读取、算法求解、实验运行和结果输出均使用模块化结构组织，最终结果统一写入 `experiments/results.csv`，并通过 Python 脚本生成对比图表。实验结果表明，动态规划和回溯法在小规模及容量可控实例上能够得到最优解，其中 FSU 正确性组中二者均命中全部 7 个参考最优值；贪心算法运行速度最快，在多数实例上能够给出较接近最优的可行解，但在部分 FSU 实例中最大误差达到 14.8127%；动态规划受容量维度影响明显，在大容量 JJ 实例上需要主动跳过；回溯法虽然加入了价值密度上界剪枝，但在部分 JJ 困难实例上仍出现超时。综合来看，动态规划适合容量可控且要求最优解的场景，回溯法适合小规模精确搜索和剪枝过程分析，贪心算法适合大规模快速近似求解场景。

## 1. 实验目的与问题定义

### 1.1 实验背景

0/1 背包问题是算法设计与分析课程中的经典问题，也是组合优化问题中的基础模型。它可以抽象许多实际场景，例如资源分配、投资组合选择、任务调度、预算分配等。在这些问题中，每个候选对象通常都有“收益”和“成本”两个属性，而系统存在总容量或总预算限制，目标是在不超过限制的情况下获得尽可能高的收益。

从算法设计角度看，0/1 背包问题具有典型的最优子结构，可以使用动态规划求解；同时它也可以通过搜索树枚举物品选或不选的状态，使用回溯法求解；此外，在工程应用中，为了提高运行速度，也常使用贪心算法获得近似解。三种方法分别代表了不同的算法思想：动态规划强调状态转移和子问题复用，回溯法强调搜索与剪枝，贪心算法强调局部选择和快速决策。

因此，本实验选择 0/1 背包问题作为研究对象，在相同数据集上比较三种算法的表现，目的是通过实际数据验证算法理论复杂度和适用场景之间的关系。

### 1.2 0/1 背包问题定义

给定 `n` 个物品，每个物品 `i` 有价值 `v_i` 和重量 `w_i`，背包容量为 `C`。每个物品只能选择一次，选择则记为 `x_i = 1`，不选择则记为 `x_i = 0`。问题目标是在总重量不超过容量的条件下，使总价值最大。

数学模型如下：

```text
max Σ v_i x_i
s.t. Σ w_i x_i <= C
x_i ∈ {0, 1}
```

其中，`x_i ∈ {0,1}` 是该问题区别于分数背包问题的重要约束。分数背包问题允许选择物品的一部分，因此可以用价值密度贪心算法得到最优解；而 0/1 背包问题中物品不可分割，简单按照价值密度排序并不能保证全局最优。这也是本实验比较贪心算法误差的重要原因。

### 1.3 实验目标

本实验主要目标如下：

1. **实现三种算法**：使用 C++17 实现动态规划、回溯法和贪心算法三种 0/1 背包求解方法。
2. **统一数据读取和输出**：支持 FSU、UU、JJ 三类数据源，将不同格式的数据统一转换为 `KnapsackInstance` 结构，并将结果写入统一 CSV 文件。
3. **验证算法正确性**：在有已知最优值的数据集上验证动态规划和回溯法是否能得到最优解。
4. **比较运行性能**：统计三种算法在不同数据规模和容量条件下的运行时间。
5. **分析近似误差**：计算贪心算法相对已知最优值的误差百分比。
6. **观察算法边界**：通过 JJ 困难实例分析动态规划的容量瓶颈和回溯法的超时现象。

### 1.4 评价维度

实验从以下维度进行对比：

| 评价维度 | 说明 |
|---|---|
| 正确性 | DP 和回溯法是否达到已知最优值 |
| 解质量 | 贪心算法结果与最优值之间的误差 |
| 时间开销 | 算法平均运行时间 `runtime_ms_avg` |
| 空间开销 | 估算内存 `memory_kb`，重点观察 DP 的容量影响 |
| 搜索效率 | 回溯法的搜索节点数、剪枝次数和剪枝率 |
| 可扩展性 | 算法是否能处理大规模或困难实例 |
| 适用边界 | 算法在何种条件下适合或不适合使用 |

## 2. 算法设计

### 2.1 动态规划算法

#### 2.1.1 算法思想

0/1 背包问题具有最优子结构：对于前若干个物品和某个容量限制，最优解可以由更小规模子问题推导而来。动态规划算法通过保存子问题结果，避免重复计算。

本实验采用一维滚动数组优化。定义：

```text
dp[c] 表示当前已经处理过的物品中，背包容量不超过 c 时能够获得的最大价值。
```

对每个物品 `(value, weight)`，状态转移为：

```text
dp[c] = max(dp[c], dp[c - weight] + value)
```

其中 `c` 从 `capacity` 倒序遍历到 `weight`。倒序遍历的原因是：0/1 背包中每个物品只能使用一次，如果容量正序遍历，同一个物品可能在当前轮被重复使用，导致算法变成完全背包问题。

#### 2.1.2 复杂度分析

动态规划算法的时间复杂度为：

```text
O(nC)
```

空间复杂度在滚动数组优化后为：

```text
O(C)
```

其中 `n` 是物品数量，`C` 是背包容量。由于复杂度与容量直接相关，当容量非常大时，即使物品数量不大，也可能造成内存和运行时间压力。因此本实验设置：

```text
DP_CAPACITY_LIMIT = 10,000,000
```

当实例容量超过该阈值时，程序不盲目分配数组，而是将状态记录为：

```text
SKIPPED_BY_CAPACITY
```

这不是算法实现失败，而是实验中对算法适用边界的主动记录。

#### 2.1.3 适用场景

动态规划适合容量不太大且要求最优解的实例。当 `C` 较小或中等时，DP 能够稳定得到最优解；但当 `C` 达到上亿甚至百亿级别时，`O(C)` 空间和 `O(nC)` 时间会成为主要瓶颈。

### 2.2 回溯法

#### 2.2.1 算法思想

回溯法将 0/1 背包问题看作一棵搜索树。每一层对应一个物品，每个物品有两种选择：选入背包或不选入背包。通过深度优先搜索遍历可能的选择组合，并在搜索过程中维护当前已选物品的总价值、总重量和当前最优解。

如果不加任何优化，回溯法最坏情况下需要枚举 `2^n` 种组合，随着物品数量增长会迅速变慢。因此本实验加入了价值密度排序和上界剪枝。

#### 2.2.2 上界剪枝

程序先按照价值密度 `value / weight` 对物品排序，然后使用分数背包思想估计当前节点的乐观上界。也就是说，在计算剩余物品可能达到的最大价值时，允许最后一个物品只取一部分。这个上界可能高于真实 0/1 背包可达到的价值，但不会低于真实最优，因此可以作为剪枝依据。

若当前价值加上剩余物品上界仍不超过当前已知最优值，则说明继续搜索该分支不可能产生更优解，可以剪枝。

剪枝条件可表示为：

```text
current_value + upper_bound <= best_value
```

本实验记录回溯法的三个搜索指标：

| 指标 | 含义 |
|---|---|
| nodes | 访问的搜索节点数 |
| pruned | 剪枝次数 |
| prune_rate | 剪枝率，约为 `pruned / nodes` |

#### 2.2.3 超时控制

回溯法最坏时间复杂度为 `O(2^n)`。在困难实例中，即使加入剪枝，也可能无法在合理时间内完成。因此程序设置 10 秒超时限制。当超过时间限制时，算法返回当前已找到的最好解，并将状态记为：

```text
TIMEOUT
```

这种设计可以避免程序长时间无响应，同时保留超时实例中的搜索节点数、剪枝次数和当前最好值，用于分析回溯法边界。

#### 2.2.4 适用场景

回溯法适合物品数量较少、需要精确求解且希望观察搜索过程的场景。对于困难实例或大规模实例，回溯法容易受到指数复杂度限制。

### 2.3 贪心算法

#### 2.3.1 算法思想

贪心算法按照物品价值密度 `value / weight` 从高到低排序，依次尝试将物品放入背包。如果当前物品重量不超过剩余容量，则选择该物品；否则跳过该物品。

算法步骤如下：

```text
1. 计算每个物品的价值密度 value / weight
2. 按价值密度从高到低排序
3. 从前到后扫描物品
4. 若当前物品能放入背包，则选择
5. 否则跳过
```

#### 2.3.2 复杂度分析

贪心算法主要耗时来自排序，因此时间复杂度为：

```text
O(n log n)
```

空间复杂度为：

```text
O(n)
```

#### 2.3.3 最优性说明

贪心算法对分数背包问题是最优的，但对 0/1 背包问题不能保证最优。原因是 0/1 背包中物品不可分割，局部最高价值密度的选择可能占用过多容量，从而排除若干低密度但组合价值更高的物品。

因此，本实验将贪心算法作为快速近似算法，并通过相对误差评价其解质量：

```text
error_percent = (optimum - value) / optimum × 100
```

### 2.4 三种算法复杂度与特点对比

| 算法 | 时间复杂度 | 空间复杂度 | 是否保证最优 | 优点 | 缺点 |
|---|---:|---:|---|---|---|
| 动态规划 | O(nC) | O(C) | 是 | 结果稳定，适合容量可控实例 | 容量大时内存和时间压力明显 |
| 回溯法 | O(2^n) | O(n) | 正常完成时是 | 可观察搜索与剪枝过程 | 大规模或困难实例可能超时 |
| 贪心算法 | O(n log n) | O(n) | 否 | 速度快，可扩展性好 | 不能保证全局最优 |

## 3. 实验数据与程序实现

### 3.1 数据源设计

本实验使用 FSU、UU、JJ 三类数据源，共 25 个实例。三类数据源在实验中的角色不同。

| 数据源 | 实例数量 | 实验角色 |
|---|---:|---|
| FSU | 8 | 正确性验证与经典小规模基准 |
| UU | 10 | 标准规模性能对比主数据源 |
| JJ | 7 | 困难实例与算法边界分析 |

#### 3.1.1 FSU 数据源

FSU 数据集中每个实例由四个文件组成：

| 文件 | 含义 |
|---|---|
| `pXX_c.txt` | 背包容量 |
| `pXX_w.txt` | 物品重量列表 |
| `pXX_p.txt` | 物品价值列表 |
| `pXX_s.txt` | 参考最优选择方案 |

程序读取参考选择方案并计算对应最优值，因此 FSU 适合用于验证动态规划和回溯法是否能得到正确结果。

#### 3.1.2 UU 数据源

UU 数据格式为：

```text
n capacity
value weight
value weight
...
```

本实验选取 UU 低维组 5 个实例和 UU 大规模组 5 个实例。低维组适合三算法完整对比，大规模组适合观察 DP 和贪心算法的运行差异，同时用于分析数据规模对算法表现的影响。

需要说明的是，UU 中 `f5_l-d_kp_15_375` 包含小数价值和重量。由于 DP 使用容量作为数组下标，程序将该实例按 10000 倍放大为整数处理，同时将最优值也按相同倍数记录。

#### 3.1.3 JJ 数据源

JJ 数据源来自困难背包实例集合，每个实例目录下包含 `test.in`，格式为：

```text
n
id profit weight
id profit weight
...
capacity
```

本实验选择 7 个有已知最优值的 JJ 实例，其中既包含 `capacity = 1,000,000` 的困难实例，也包含 `capacity = 100,000,000` 和 `capacity = 10,000,000,000` 的大容量实例。JJ 数据用于观察 DP 的容量边界和回溯法在困难实例上的超时现象。

## 4. 实验结果与分析

本节基于 `experiments/results.csv` 和 `reports/figures/final/` 中的最终图表进行分析。最终报告建议使用以下图表：

### 4.1 FSU 正确性验证

FSU 正确性组包含 `p01` 到 `p07` 共 7 个小规模实例。实验结果显示，动态规划算法在 7 个实例上全部命中参考最优值，回溯法也在 7 个实例上全部命中参考最优值。这说明：

1. FSU 数据读取逻辑正确；
2. DP 状态转移和容量倒序遍历逻辑正确；
3. 回溯法搜索与上界剪枝逻辑没有破坏最优性；
4. 统一结果输出中的 `value` 和 `optimum` 字段能够正确对应。

贪心算法在 FSU 上并不总是最优。FSU 正确性组中，贪心平均误差为 5.1183%，最大误差为 14.8127%。其中部分实例贪心能够达到最优，例如 p01；但在 p06 等实例中，贪心误差较明显。这说明价值密度排序虽然直观，但它只考虑单个物品的局部性价比，没有考虑多个物品组合后的整体价值。

该结论对应图表：

```text
reports/figures/final/fig1_fsu_correctness_error.png
```

图中用贪心误差柱状图展示 FSU 各实例误差，并标注 DP 和回溯法均命中最优值。相比直接画三算法 value，这种图更能突出“精确算法正确、贪心存在误差”的核心结论。

### 4.2 UU 标准规模性能分析

UU 数据源是本实验的标准规模性能对比主数据源。UU 低维组包含 f1、f2、f5、f8、f10 五个实例，适合三种算法完整对比。

从结果看，UU 低维组中 DP 和回溯法均能够达到已知最优值，贪心算法也能快速得到可行解，并且误差整体较小。UU 低维组中贪心平均误差为 0.3348%，最大误差为 0.5859%。这说明在某些标准实例上，价值密度贪心虽然不能从理论上保证最优，但实际近似效果较好。

该结论对应图表：

```text
reports/figures/final/fig2_uu_low_runtime.png
```

需要注意的是，小规模实例中部分运行时间记录为 0.0000 ms，这是因为实际运行时间低于计时精度。绘图时采用最小显示值处理，以避免 log 坐标无法显示 0。这并不改变原始实验结果，只是为了图表表达更加清晰。

UU 大规模组中，本实验重点观察 `knapPI_1_100_1000_1`、`knapPI_1_500_1000_1`、`knapPI_1_1000_1000_1` 三个 uncorrelated 实例。随着 n 从 100 增加到 1000，DP 的状态转移次数增加，运行时间也随之增长；贪心算法主要开销来自排序，在大规模数据上仍保持较低时间开销。

对应图表：

```text

```

该图展示了 DP 和 Greedy 在不同规模下的运行时间趋势。可以看出，贪心算法的可扩展性更好，而 DP 在容量可控的情况下仍能得到最优值，但运行代价更高。

### 4.3 贪心算法误差分析

贪心算法的主要优势是速度快，主要风险是不能保证最优。因此本实验重点统计其相对误差。

从全部数据源看，贪心算法在 FSU、UU、JJ 上均能输出可行解，并且没有出现超容量情况。但误差分布存在明显差异：

- FSU 中贪心平均误差为 5.1183%，最大误差为 14.8127%；
- UU 低维组中贪心平均误差为 0.3348%，最大误差为 0.5859%；
- JJ 中贪心平均误差为 0.0292%，最大误差为 0.0576%。

对应图表：

```text
reports/figures/final/fig4_greedy_error.png
```

从这些结果可以看出，贪心算法的误差与数据分布有关。在某些数据集中，高价值密度物品组合恰好接近最优组合，因此误差较小；而在另一些数据集中，局部高密度选择可能阻碍后续更优组合，导致误差增大。

因此，贪心算法适合作为快速近似方法，但不适合作为需要严格最优性的唯一方法。在实际应用中，如果问题规模较大且允许少量误差，贪心算法具有较好工程价值；如果必须得到最优解，则应使用 DP、回溯法或其他精确算法。

### 4.4 回溯法剪枝与超时分析

回溯法在理论上可以通过枚举所有选择组合得到最优解，但最坏时间复杂度为 `O(2^n)`。本实验通过价值密度排序和分数背包上界进行剪枝，以减少搜索节点。

在 FSU 和 UU 低维实例中，回溯法能够正常完成，并得到与 DP 一致的最优值。对于这些小规模实例，剪枝能够有效减少搜索量，节点数处于可接受范围。

但在 JJ 困难实例中，回溯法出现 5 个 TIMEOUT。这表明，即使加入剪枝，回溯法在困难实例上仍然可能受到指数搜索空间限制。

图中使用对数坐标展示搜索节点数，并用红色突出 TIMEOUT 实例。可以看出，部分 JJ 实例的搜索节点数非常大，说明回溯法的运行时间不仅取决于 n，还受到数据结构、上界估计效果和最优解分布的影响。

回溯法的实验意义不只在于求解结果，也在于展示搜索算法的边界：当问题规模或困难程度增加时，即使剪枝能够减少大量无效分支，仍可能无法避免指数复杂度带来的超时问题。

### 4.5 JJ 困难实例边界分析

JJ 数据源用于观察困难实例下三种算法的边界表现。实验中，JJ 共包含 7 个实例，其中 5 个容量为 1,000,000，另外 2 个为大容量边界实例。

实验结果显示：

- DP 在 5 个 JJ 实例上正常完成；
- DP 在 2 个大容量 JJ 实例上被标记为 `SKIPPED_BY_CAPACITY`；
- 回溯法在 5 个 JJ 实例上出现 `TIMEOUT`；
- 贪心算法在 JJ 实例上均能正常完成。

对应图表：

```text
reports/figures/final/fig6_jj_boundary.png
```

该图以矩阵形式展示了三种算法在 JJ 数据上的状态分布。它说明：

1. DP 的瓶颈主要来自容量维度，而不是单纯来自物品数量；
2. 回溯法的瓶颈主要来自搜索空间，即使容量不极端也可能超时；
3. 贪心算法不依赖容量维度建立数组，也不搜索指数状态，因此在困难实例上具有较强可扩展性。

这一结果与理论复杂度分析一致，也体现了本实验“精确性—时间—规模”之间的核心权衡。

### 4.6 综合对比分析

综合三类数据源和三种算法结果，可以得到以下结论。

#### 4.6.1 正确性方面

动态规划和回溯法在正常完成时均能得到最优值。FSU 和 UU 低维组中的实验结果验证了这一点。贪心算法不能保证最优，但始终能够快速得到可行解。

#### 4.6.2 时间性能方面

贪心算法最快，适合大规模或实时性要求较高的场景。DP 在容量可控时可以接受，但当容量变大时运行时间和空间都会增加。回溯法在小规模下可行，但在困难实例中可能超时。

#### 4.6.3 空间开销方面

DP 的空间复杂度为 `O(C)`，因此容量越大，内存压力越明显。本实验中 p08 和 JJ 容量较大的实例体现了这一点。贪心算法和回溯法不需要建立容量数组，因此在容量维度上不如 DP 敏感。

#### 4.6.4 解质量方面

贪心算法在 UU 和 JJ 的部分实例上误差较小，但在 FSU 某些实例中误差较大。这说明贪心误差不能仅根据算法本身判断，还与数据分布密切相关。

#### 4.6.5 适用边界方面

| 场景 | 推荐算法 | 原因 |
|---|---|---|
| 容量较小且要求最优 | 动态规划 | 稳定得到最优解 |
| 物品数量较少且希望分析搜索过程 | 回溯法 | 能展示选/不选搜索和剪枝效果 |
| 大规模且允许近似 | 贪心算法 | 速度快、实现简单、可扩展性好 |
| 容量极大 | 贪心或回溯限时 | DP 容量数组不可接受 |
| 困难实例 | 贪心给近似，DP/回溯视条件运行 | 精确算法可能跳过或超时 |

## 5. 总结

### 5.1 实验结论

本实验围绕 0/1 背包问题，使用 FSU、UU、JJ 三类数据源，对动态规划、回溯法和贪心算法进行了对比分析。实验结果验证了算法理论分析中的主要结论：

1. **动态规划算法**能够稳定得到最优解，但时间和空间复杂度受容量 `C` 影响明显。对于容量较小或中等的实例，DP 是可靠的精确算法；对于超大容量实例，需要主动跳过或采用其他方法。
2. **回溯法**在小规模实例中能够得到最优解，并且可以通过上界剪枝减少搜索节点。但其最坏复杂度仍为指数级，在 JJ 困难实例中出现了超时现象。
3. **贪心算法**速度最快，能够处理全部实验实例，并且在部分数据源中误差较小。但由于 0/1 背包不满足简单价值密度贪心的全局最优性质，贪心算法不能作为严格最优解算法。

从整体上看，三种算法体现了典型的算法取舍关系：动态规划强调最优性，回溯法强调搜索与剪枝，贪心算法强调速度和可扩展性。实际使用时，应根据问题规模、容量大小、是否要求最优解以及可接受误差来选择算法。

### 5.2 实验不足

本实验仍存在一些不足：

1. **内存统计为估算值**：实验中的 `memory_kb` 主要根据数据结构大小估算，并非系统真实峰值内存。
2. **回溯法只采用一种上界策略**：本实验使用价值密度和分数背包思想计算上界，未比较其他剪枝策略。
3. **数据规模仍然有限**：虽然使用了三类数据源，但报告重点展示的实例数量有限，后续可增加更多规模梯度。
4. **贪心算法只使用一种排序规则**：本实验只采用价值密度排序，未比较按价值、按重量或混合启发式排序的效果。
5. **图表仍需根据正式排版调整**：当前图表适合报告和 PPT 初稿，最终提交前还可以根据页面大小进一步调整。

### 5.3 改进方向

后续可以从以下方向改进：

1. 加入分支限界法，与回溯法进行更细致比较；
2. 使用系统 API 或性能分析工具统计真实峰值内存；
3. 增加更多 UU 大规模实例，进一步观察规模增长趋势；
4. 对 JJ 数据选择更多参数组合，分析困难实例结构对算法表现的影响；
5. 比较不同贪心策略或近似算法，例如按价值排序、按重量排序、局部搜索改进等；
6. 将实验结果导出为更适合论文排版的表格和矢量图。
