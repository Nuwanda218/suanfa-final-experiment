### 7.2 readers/fsu_reader.cpp

职责：读取 FSU 四文件格式。

读取步骤：

1. 从 `path` 得到前缀，例如 `data/FSU/p01`；
2. 读取 `p01_c.txt` 得到容量；
3. 读取 `p01_w.txt` 得到重量数组；

### 7.3 readers/uu_reader.cpp

职责：读取 UU 单文件格式。

读取格式：

```text
n capacity
value weight
value weight
...
```

读取步骤：

1. 第一行读取 `n` 和 `capacity`；
2. 后续读取 `n` 行 `value weight`；
3. 最优值从 `DatasetConfig::optimum` 传入；
4. 生成统一 `KnapsackInstance`。

验证重点：

- 实际读取物品数量必须等于第一行 `n`；
- 如果配置中 `n`、`capacity` 非空，应与文件内容一致；
- 如果不一致，在 `run_log.txt` 中记录警告。

### 7.4 readers/jj_reader.cpp

职责：读取 JJ 困难实例格式。

读取格式：

```text

id profit weight
id profit weight
...
capacity
```

读取步骤：

1. 第一行读取物品数量 `n`；
2. 连续读取 `n` 行，每行包含 `id profit weight`；
3. 最后一行读取容量；
4. 最优值从 `datasets.csv` 中读取；
5. 转换为统一 `KnapsackInstance`。

验证重点：

- `test.in` 是否存在；
- 读取物品数是否等于 `n`；
- `optimum = -1` 时仍可运行贪心，但误差为 `NA`；
- 大容量实例应能被读取，但 DP 可能跳过。

## 8. 阶段 5：三种算法实现

### 8.1 algorithms/greedy_knapsack.h 与 .cpp

实现内容：

- 按价值密度 `value / weight` 降序排序；
- 依次尝试放入物品；
- 若当前物品重量不超过剩余容量，则选择；
- 返回总价值、总重量、选择数量、运行时间。

复杂度：

```text
时间复杂度：O(n log n)
空间复杂度：O(n)
```

中文注释重点：

- 解释价值密度的含义；
- 解释为什么贪心适合快速近似；
- 说明 0/1 背包中贪心不能保证全局最优；
- 说明贪心结果主要用于与最优值计算误差。

验证数据：

- FSU p01-p07；
- UU f1、f2；
- JJ 任意一个小样本。

### 8.2 algorithms/dp_knapsack.h 与 .cpp

实现内容：

- 使用一维滚动数组 `dp[c]`；
- 外层遍历物品；
- 内层容量从大到小遍历；
- 返回最优价值；
- 可选：为了统计总重量和选择数量，后期可增加选择恢复；如果实现恢复过于复杂，结果中 `total_weight` 和 `selected_count` 可先填 `NA` 或用辅助数组恢复。

建议实现方案：

1. 第一版只保证 `value` 正确；
2. 第二版增加选择恢复：记录每个容量最后一次选择的物品，或在小规模下使用二维记录；
3. 如果恢复会显著增加复杂度，报告中重点使用价值、时间、内存即可。

容量保护：

```cpp
if (instance.capacity > DP_CAPACITY_LIMIT) {
    status = "SKIPPED_BY_CAPACITY";
}
```

复杂度：

```text
时间复杂度：O(nC)
空间复杂度：O(C)
```

中文注释重点：

- 解释 `dp[c]` 的状态含义；
- 解释为什么容量必须倒序遍历，避免同一物品被重复选择；
- 解释滚动数组如何把二维 DP 压缩成一维；
- 解释容量阈值是为了避免 JJ 大容量实例导致内存或时间失控。

验证数据：

- FSU p01-p07：DP 结果应等于参考最优值；
- UU f1、f2、f8、f10：DP 结果应等于已知最优值；
- 超过阈值的数据应输出 `SKIPPED_BY_CAPACITY`。

### 8.3 algorithms/backtracking_knapsack.h 与 .cpp

实现内容：

- 将物品按价值密度降序排序；
- 使用 DFS 搜索“选/不选”两种分支；
- 用分数背包思想计算上界；
- 若上界不可能超过当前最优，则剪枝；
- 记录访问节点数 `nodes`；
- 记录剪枝次数 `pruned`；
- 设置 10 秒超时；
- 超时后返回当前已找到的最好值，状态为 `TIMEOUT`。

关键函数：

```cpp
double bound(int index, long long currentWeight, long long currentValue);
void dfs(int index, long long currentWeight, long long currentValue);
```

复杂度：

```text
最坏时间复杂度：O(2^n)
空间复杂度：O(n)
```

中文注释重点：

- 解释回溯树中每一层对应一个物品；
- 解释“选择当前物品”和“不选择当前物品”两条分支；
- 解释为什么按价值密度排序有助于更早得到较好的上界和初始解；
- 详细解释分数背包上界：剩余容量可以按密度装满，得到一个理想化的乐观估计；
- 解释剪枝条件：如果乐观上界仍不超过当前最优值，就没有继续搜索的必要；
- 解释超时返回不是算法错误，而是实验中体现指数复杂度边界的证据。

验证数据：

- FSU p01-p07：应尽量得到最优值；
- UU 低维：应尽量得到最优值；
- UU 大规模和 JJ：可能 `TIMEOUT`，属于预期现象；
- 回溯结果中 `nodes`、`pruned`、`prune_rate` 应有实际数值。

## 9. 阶段 6：实验运行器与 CSV 输出实现

### 9.1 runner/experiment_runner.h 与 .cpp

职责：批量运行实验。

主要流程：

1. 读取 `data/datasets.csv`；
2. 过滤 `enabled = 1` 的数据；
3. 对每个数据集加载实例；
4. 根据数据分组决定重复次数；
5. 依次运行 DP、回溯、贪心；
6. 应用 DP 容量限制和回溯超时规则；
7. 计算误差；
8. 将结果交给 `ResultWriter`。

建议运行策略：

| group | DP | Backtracking | Greedy | repeat |
|---|---|---|---|---:|
| fsu_correctness | 运行 | 运行 | 运行 | 5 |
| uu_low | 运行 | 运行 | 运行 | 5 |
| uu_large | 运行 | 限时运行 | 运行 | 3 |
| jj_hard | 按容量阈值运行 | 限时运行 | 运行 | 1 |

注意：回溯法本身可能很慢，建议无论 group 如何都只运行 1 次，并在 `repeat_times` 中如实记录。

### 9.2 runner/result_writer.h 与 .cpp

职责：写出实验结果。

主结果文件：

```text
experiments/results.csv
```

字段：

```text
source,group,dataset,n,capacity,algorithm,status,optimum,value,total_weight,selected_count,error_percent,runtime_ms_avg,memory_kb,repeat_times,nodes,pruned,prune_rate
```

辅助输出：

```text
experiments/run_log.txt
experiments/timeout_cases.csv
experiments/summary.csv
```

实现建议：

- `results.csv` 每次完整运行时重写；
- `run_log.txt` 记录读取警告、跳过原因、运行开始结束时间；
- `timeout_cases.csv` 只记录回溯超时的数据；
- `summary.csv` 可后期由 Python 汇总生成。

### 9.3 误差计算规则

若 `optimum > 0`：

```text
error_percent = (optimum - value) / optimum * 100
```

若 `optimum <= 0`：

```text
error_percent = NA
```

若算法状态不是 `OK`，误差也可以记为 `NA`，但对于 `TIMEOUT` 回溯如果返回了当前最好值，可以额外保留 `value` 作为参考。

### 9.4 内存估算规则

精确跨平台峰值内存统计实现较复杂，本实验可采用估算方式：

- DP：约为 `(capacity + 1) * sizeof(long long) / 1024` KB；
- 贪心：约为 `n * sizeof(Item) / 1024` KB；
- 回溯：约为 `n * sizeof(Item) + recursion_depth` 的近似值。

报告中需说明：`memory_kb` 是估算值，主要用于体现 DP 的容量相关空间压力。
