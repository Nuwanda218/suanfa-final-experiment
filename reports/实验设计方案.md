## 1. 实验总体定位与研究问题

### 1.1 实验定位

本结课实验以已提交的选题报告为基础，保持原有选题不变：

> **0/1背包问题三种算法求解性能对比**

课程类型属于 **2.3 问题求解类**：针对附件数据集中的一个问题，选取至少 3 个数据集，使用至少 3 种算法进行求解，并分析不同算法解决同一问题时的复杂度、优缺点和适用范围。

本实验选择的问题为 **0/1背包问题**。给定 `n` 个物品，每个物品具有价值 `v_i` 和重量 `w_i`，背包容量为 `C`，目标是在总重量不超过 `C` 的前提下最大化总价值：

```text
max Σ v_i x_i
s.t. Σ w_i x_i <= C
x_i ∈ {0, 1}
```

实验固定采用三种算法：

1. **动态规划算法（Dynamic Programming, DP）**
2. **回溯法（Backtracking）**
3. **贪心算法（Greedy）**

其中，动态规划和回溯法属于精确求解算法；贪心算法属于快速近似算法。三者能够形成“最优性、时间开销、空间开销、可扩展性”之间的对比。

### 1.2 实验风格

本实验采用 **对比分析型** 风格，而不是只完成算法实现。实验不仅回答“三种算法能不能运行”，还要回答：

> 在不同数据规模、不同容量、不同数据来源、不同实例难度下，三种算法分别表现如何？

因此，实验重点包括：

| 维度 | 分析内容 |
|---|---|
| 正确性 | DP 和回溯是否能达到已知最优值 |
| 解质量 | 贪心结果与最优值之间的误差 |
| 时间代价 | 不同算法在不同规模下的运行时间 |
| 空间代价 | DP 受容量维度影响的内存压力 |
| 搜索效率 | 回溯法的搜索节点数、剪枝次数和是否超时 |
| 可扩展性 | 算法能否处理大规模或困难实例 |
| 适用边界 | 总结每种算法适合什么场景、不适合什么场景 |

### 1.3 核心研究问题

本实验围绕以下问题展开：

#### 问题一：精确算法与近似算法的差异

动态规划和回溯法通常可以得到最优解，但需要更多计算资源；贪心算法运行速度快，但不能保证最优。实验需要量化：

- 贪心算法相对 DP、回溯快多少；
- 贪心算法误差有多大；
- 在哪些数据上贪心误差较小；
- 在哪些数据上贪心误差明显。

#### 问题二：动态规划的瓶颈在哪里

动态规划的时间和空间复杂度主要受 `n` 和容量 `C` 影响。实验需要观察：

- 当物品数量增加时，DP 时间如何变化；
- 当容量很大时，DP 是否出现明显内存压力；
- 滚动数组优化后，DP 是否仍然受容量限制；
- 为什么 DP 适合容量不太大的中小规模问题。

#### 问题三：回溯法的剪枝效果如何

回溯法理论最坏复杂度是指数级，但加入贪心上界剪枝后，小规模数据上可能表现较好。实验需要记录：

- 回溯法是否能得到最优解；
- 搜索节点数；
- 剪枝次数；
- 剪枝率；
- 哪些规模开始明显变慢；
- 在大规模或困难实例上是否会超时。

#### 问题四：不同数据源对算法表现有什么影响

本实验正式使用三类数据源：

| 数据源 | 实验角色 |
|---|---|
| FSU | 正确性验证与经典小规模基准 |
| UU | 标准规模性能对比主数据源 |
| JJ | 困难实例正式对比数据源 |

最终报告应形成如下分析逻辑：FSU 用于验证算法正确性，UU 用于观察标准规模下的性能变化，JJ 用于检验困难实例下算法的边界。通过三类数据源的分层实验，更全面地比较 DP、回溯和贪心算法在 0/1 背包问题上的优缺点。

### 1.4 预期结论方向

实验最终形成以下定量或半定量结论：

1. **动态规划**：能稳定得到最优解，但时间和空间受容量 `C` 影响明显；适合容量不太大且要求最优解的实例。
2. **回溯法**：小规模下可得到最优解，剪枝后效率可能较好；规模扩大后容易出现指数级增长；适合物品数量较少且需要精确解的问题。
3. **贪心算法**：速度最快，可处理很大规模实例；不能保证最优解，存在相对误差；适合大规模、实时性强、允许近似解的场景。
4. **多数据源对比**：FSU 适合验证正确性，UU 适合做规模增长实验，JJ 适合观察困难实例下算法边界。

4. 贪心算法与最优解之间是否存在误差；

### 2.3 第三层：JJ 困难实例正式对比实验

JJ 数据集位于 `数据集/JJ/`，来自论文 *A new class of hard problem instances for the 0-1 knapsack problem*。每个实例在独立文件夹中，`test.in` 格式为：

```text

id profit weight
id profit weight
...

```

最优值记录在 `数据集/JJ/optima.csv` 中。若 `optimum = -1`，表示原求解器未能得到最优值，正式实验中应避开或标记为无基准。

JJ 作为正式第三数据源，但采用抽样策略，不全量运行。建议选择 5 到 8 个实例，原则为：

1. `optima.csv` 中最优值不是 `-1`；
2. 实例文件存在；
3. 优先覆盖不同 `n`；
4. 优先选择 `capacity = 1,000,000`；
5. 可加入 1 到 2 个更大容量实例作为 DP 边界观察。

| 类别 | 建议 |

| 基础困难实例 | n=400, C=1,000,000 |
| 中等困难实例 | n=600, C=1,000,000 |
| 较高规模实例 | n=800, C=1,000,000 |
| 高规模实例 | n=1000, C=1,000,000 |
| 大容量实例 | n=400, C=100,000,000 |
| 极端容量实例 | n=400, C=10,000,000,000 |

JJ 层主要回答：困难实例下贪心是否仍能快速给出结果，DP 是否受容量限制，回溯法是否会超时，理论复杂度是否能在真实困难实例中体现出来。

### 2.4 总体数据集选择建议

最终正式报告重点使用：

- FSU：`p01` 到 `p07`，`p08` 作为容量压力样例；
- UU 低维：`f1`、`f2`、`f5`、`f8`、`f10`；
- UU 大规模：`knapPI_1_100`、`knapPI_1_500`、`knapPI_1_1000`、`knapPI_2_100`、`knapPI_3_100`；

## 3. 算法设计与程序结构

### 3.1 总体程序设计思想

程序目标不是写三个孤立算法，而是建立统一实验程序：不同数据源读入后转换成统一 0/1 背包实例结构；三种算法接收同一种输入；所有算法输出统一结果格式；最终统一写入 CSV。

整体数据流：

```text
原始数据文件
  ↓
数据读取模块
  ↓
统一 KnapsackInstance
  ↓
DP / Backtracking / Greedy
  ↓
统一 SolveResult
  ↓
results.csv
  ↓
Python 脚本 / 表格工具绘图
  ↓
实验报告与 PPT
```

### 3.2 统一数据结构

物品结构：

```cpp
struct Item {
    int id;
    long long value;
    long long weight;
};
```

背包实例结构：

```cpp
struct KnapsackInstance {
    string source;
    string name;
    int n;
    long long capacity;
    vector<Item> items;
    long long optimum;
};
```

算法结果结构：

```cpp
struct SolveResult {
    string algorithm;
    long long value;
    long long total_weight;
    int selected_count;
    double runtime_ms;
    long long memory_kb;
    string status;
    long long nodes;
    long long pruned;
};
```

### 3.3 数据读取模块

由于三个数据源格式不同，设计三个读取模块：

1. FSU reader：读取 `pXX_c.txt`、`pXX_w.txt`、`pXX_p.txt`、`pXX_s.txt`，并根据参考选择方案计算最优值。
2. UU reader：读取 `n capacity` 与后续 `value weight` 格式，并从配置中读取最优值。
3. JJ reader：读取 `test.in` 中的 `id profit weight` 格式，并从 `optima.csv` 或 `datasets.csv` 读取最优值。

三种 reader 最终都返回统一的 `KnapsackInstance`。

### 3.4 动态规划算法

动态规划使用一维滚动数组：

```text
dp[c] 表示容量不超过 c 时可以获得的最大价值
```

状态转移：

```cpp
for item in items:
    for c from capacity down to item.weight:
        dp[c] = max(dp[c], dp[c - item.weight] + item.value);
```

复杂度：

| 指标 | 复杂度 |
|---|---|
| 时间复杂度 | O(nC) |
| 空间复杂度 | O(C) |

由于 JJ 中可能存在巨大容量，设置 `DP_CAPACITY_LIMIT`。超过阈值时不盲目运行，状态记为 `SKIPPED_BY_CAPACITY`。

### 3.5 回溯法

回溯法采用深度优先搜索，并加入贪心上界剪枝：

1. 按价值密度 `value / weight` 从高到低排序；
2. 从第一个物品开始递归；
3. 每个物品有“选”和“不选”两种分支；
4. 用分数背包思想估计剩余物品可达到的价值上界；
5. 若 `当前价值 + 上界 <= 当前最优值`，则剪枝。

回溯法记录：

| 指标 | 含义 |
|---|---|
| nodes | 递归访问节点数 |
| pruned | 剪枝次数 |
| prune_rate | 剪枝率 |
| status | OK 或 TIMEOUT |

复杂度：

| 指标 | 复杂度 |
|---|---|
| 最坏时间复杂度 | O(2^n) |
| 空间复杂度 | O(n) |

回溯必须设置时间限制，超时记为 `TIMEOUT`。

### 3.6 贪心算法

贪心算法按价值密度 `value / weight` 从高到低排序，遍历物品，能装入则选择，不能装入则跳过。

复杂度：

| 指标 | 复杂度 |
|---|---|
| 时间复杂度 | O(n log n) |
| 空间复杂度 | O(n) |

若存在已知最优值，贪心误差计算为：

```text
error_percent = (optimum - greedy_value) / optimum × 100%
```

### 3.8 代码中文注释规范

后续实现代码时，源码中应保留足够详细的中文注释，目的是便于本人复习、理解和在报告或答辩中回顾代码逻辑。注释不只解释“这一行做什么”，更要解释“为什么这样做”。

具体要求如下：

1. **文件级注释**：每个 `.h` 和 `.cpp` 文件开头说明该文件的作用、所属模块、主要函数和与其他模块的关系。
2. **结构体注释**：对 `Item`、`KnapsackInstance`、`DatasetConfig`、`SolveResult` 等核心结构体逐字段说明含义，尤其说明 `optimum`、`status`、`nodes`、`pruned` 等实验指标字段。
3. **数据读取注释**：在 FSU、UU、JJ 三种 reader 中说明各数据源的原始格式、读取步骤和转换为统一结构的过程。
4. **算法步骤注释**：在 DP、回溯、贪心算法实现中，用中文解释关键步骤，例如 DP 状态含义、容量倒序遍历原因、回溯的选/不选分支、贪心排序依据等。
5. **复杂度注释**：在每个算法入口函数附近注明时间复杂度、空间复杂度和主要瓶颈，例如 DP 的容量瓶颈、回溯的指数级瓶颈、贪心不能保证最优。
6. **剪枝逻辑注释**：回溯法中的上界估计、剪枝条件、节点数和剪枝次数统计必须写清楚，便于报告中解释剪枝效果。
7. **实验规则注释**：对 DP 容量阈值、回溯超时、重复运行次数、`TIMEOUT`、`SKIPPED_BY_CAPACITY` 等状态的设置原因进行说明。
8. **避免无意义注释**：不需要给显而易见的语句写机械注释，例如 `i++`、简单赋值等；重点解释算法思想、实验设计和容易忘记的实现细节。

整体注释风格应服务于课程实验复盘：代码既要能运行，也要能帮助阅读者理解三种算法和实验流程。

## 4. 实验矩阵、运行规则与评价指标

### 4.1 总体实验矩阵

本实验采用：

```text
三类数据源 × 三种算法 × 多维评价指标
```

| 数据源 | DP | 回溯法 | 贪心 |
|---|---|---|---|
| FSU | 运行 | 运行 | 运行 |
| UU 低维 | 运行 | 运行 | 运行 |
| UU 大规模 | 运行 | 限时运行/超时记录 | 运行 |
| JJ 困难实例 | 按容量阈值运行/跳过 | 限时运行/超时记录 | 运行 |

小规模数据上三种算法完整比较；大规模和困难数据上保留不可运行、超时、跳过等状态，作为算法适用边界的证据。

### 4.2 运行规则

#### DP 容量限制规则

动态规划复杂度为 `O(nC)` 和 `O(C)`。建议设置：

```text
DP_CAPACITY_LIMIT = 10,000,000
```

若容量超过阈值，状态记录为：

```text
SKIPPED_BY_CAPACITY
```

这样可以避免在 `C=100,000,000` 或 `C=10,000,000,000` 的 JJ 实例上造成程序失控。

#### 回溯超时规则

建议设置：

```text
BACKTRACKING_TIME_LIMIT = 10 seconds
```

超时状态记录为：

```text
TIMEOUT
```

同时记录已搜索节点数、剪枝次数和当前已找到的最好结果。

#### 重复运行规则

| 数据类型 | 重复次数 |
|---|---:|
| FSU 小规模 | 5 次 |
| UU 低维 | 5 次 |
| UU 大规模 | 3 次 |
| JJ 困难实例 | 1 次 |
| 回溯法 | 1 次或限时 1 次 |

结果字段使用 `runtime_ms_avg` 表示平均运行时间。

#### 最优值与误差规则

若数据集有已知最优值：

```text
error_percent = (optimum - value) / optimum × 100
```

若最优值未知或为 `-1`，则误差记为 `NA`。
